# The Naming Laws of Variables
![[Untitled design (2) 1.png]]
🌟 As you may notice, we can't use spaces when naming variables, as such, we really only have 2 ways of naming variables: **camelCase** (hiMyNameIsBrooke) & **snake_case** (hi_my_name_is_brooke). You can use either/or in your Java programs, but it's standard (in Java) to name your variables in **camelCase** (*If you're wondering, snake_case is the convention of Python, while JavaScript actually sticks to camelCase too*).

Additionally, we do have a few more laws that we must follow when naming our Java variables:

| Rule                                      | Description                                                       | Example (Valid)                           | Example (Invalid)          |
| ----------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------- | -------------------------- |
| **Must start with a letter, `$`, or `_`** | Can't start with a number                                         | `age`, `_temp`, `$price`                  | `1age` ❌                   |
| **Case-sensitive**                        | `age` and `Age` are treated as two completely different variables | `age`, `Age` (both valid, but different!) | —                          |
| **Can't be a reserved keyword**           | Words Java already uses for its own syntax are off-limits         | `classType`                               | `class` ❌, `int` ❌, `if` ❌ |

## Example!
```java
// Valid
int age = 21;
String myAge = "21"; // camelCase convention

// Case-sensitivity — these are TWO DIFFERENT variables
int age = 21;
int Age = 99;
System.out.println(age); // 21
System.out.println(Age); // 99, Java does not care that this looks confusing

// Invalid — will NOT compile
int 1age = 21;   // ❌ can't start with a number
int class = 1;   // ❌ "class" is a reserved keyword

// Legal, but bad practice
int x = 30;       // compiles fine, but it isn't descriptive, x is for what?
int TwinsAge = 26; // works, but breaks camelCase convention
```
